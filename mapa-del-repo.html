Mapa de Open MCT para conectar a Percy

Open MCT es como el tablero de un coche, pero para una misión espacial: una página web que la NASA usa para ver en pantalla, en tiempo real, los datos que envía una nave, un rover o un satélite.

Este mapa explica cómo está construido y cómo viajaría un dato de Perseverance («Percy») hasta convertirse en una gráfica. Cada caja lleva su archivo:línea por si alguien quiere ver el código exacto. Todas las rutas son relativas a la raíz del repositorio nasa/openmct.

Cómo funciona, en un diagrama

Open MCT tiene un núcleo pequeño (el «chasis») y muchos plugins (las «piezas que se enchufan»). Casi todo lo que ves en pantalla —gráficas, tablas, relojes— es un plugin. Para conectar a Percy escribiremos nuestro propio plugin.

Las 5 piezas clave para conectar a Percy

Todo esto vive dentro de un solo plugin nuestro. Ninguna pieza toca el código de la NASA.

1

El plugin «Percy»

Una función que el núcleo llama una vez al arrancar. Dentro registramos las otras cuatro piezas.

Es como el enchufe: sin él, nada de lo demás se conecta.

src/MCT.js:435-437
2

La carpeta y sus objetos

Una carpeta «Percy» en el árbol, y dentro un objeto por cada sensor: velocidad, rumbo, inclinación, batería…

Es el índice: lo que el operador ve en el menú lateral.

src/api/objects/ObjectAPI.js:498 src/api/objects/ObjectAPI.js:168
3

El tipo «canal de Percy»

Le enseña al sistema qué es un canal de telemetría de Percy, con su nombre e icono.

Es la etiqueta de la caja: «esto contiene datos de Percy».

src/api/types/TypeRegistry.js:59
4

La ficha de cada dato (metadatos)

Dice que cada dato trae una hora (utc, eje X) y un valor (eje Y), con sus unidades.

Sin esta ficha, la gráfica no sabe qué número poner en cada eje y ni siquiera aparece.

5

El proveedor de telemetría

El traductor entre Percy y Open MCT: responde «dame lo de ayer de 10:00 a 11:00» (historial) y «avísame de cada dato nuevo» (en vivo).

Es la única pieza que sabe de dónde vienen los datos de verdad.

Cómo conectamos Percy

Nuestra fuente de datos más directa es nuestra propia simulación 3D de Percy (la que ya maneja con W/A/S/D): ya sabe en todo momento su posición, rumbo y velocidad. Los pasos:

  1. Elegir qué datos mostrar.

    Empezar con 4 canales sencillos: velocidad (m/s), rumbo (°), inclinación (°) y distancia recorrida (m). Cada dato es siempre una pareja: hora + valor, por ejemplo { utc: 1739462400000, value: 3.2 } (la hora va en milisegundos).

  2. Hacer que la simulación «emita» su telemetría.

    La simulación envía unas 10 veces por segundo sus datos por una conexión en vivo (WebSocket) a un pequeño servidor, que además guarda el historial para poder responder «qué pasó entre las 10:00 y las 11:00».

  3. Crear el plugin «Percy» (pieza 1).

    Un archivo nuevo, percy-plugin.js, con una función de instalación igual a la de los plugins de la NASA.

  4. Añadir la carpeta «Percy» y sus canales (piezas 2 y 3).

    Una carpeta raíz en el árbol y, dentro, un objeto por canal, todos del tipo «canal de Percy».

  5. Escribir la ficha de cada canal (pieza 4).

    Marcar utc como el tiempo (domain) y value como el valor (range), con su unidad. La clave del tiempo debe llamarse igual que el sistema de tiempo activo (utc).

  6. Escribir el proveedor (pieza 5).

    Dos funciones: historial (pide al servidor los datos entre dos horas y los devuelve en una lista) y en vivo (escucha el WebSocket y entrega cada dato nuevo).

  7. Enchufar el plugin en la página.

    Una línea en el archivo de inicio, junto a los demás plugins y antes de arrancar, igual que se hace con el generador de ejemplo (index.html:104).

  8. Abrir «Percy → Velocidad».

    Si la ficha está bien, Open MCT ofrece la gráfica él solo. Después se pueden combinar varios canales en un «Display Layout» para montar un tablero de misión completo.

Sobre datos reales de la NASA: el Percy real no publica su telemetría en directo. Lo público llega con retraso (imágenes en bruto, el tiempo meteorológico de su estación MEDA…). El mismo plugin serviría: solo cambiaría el proveedor (paso 6) para leer esas fuentes en lugar de nuestra simulación.
Para quien programe: esqueleto del plugin (orientativo, sin probar) 
export default function PercyPlugin({ url = 'ws://localhost:8090' } = {}) {
  return function install(openmct) {
    // Pieza 2: carpeta raíz + objetos
    openmct.objects.addRoot({ namespace: 'percy', key: 'root' });
    openmct.objects.addProvider('percy', { get: (id) => obtenerObjeto(id) });

    // Pieza 3: tipo
    openmct.types.addType('percy.telemetry', {
      name: 'Canal de Percy', cssClass: 'icon-telemetry', creatable: false
    });

    // Pieza 5: proveedor (historial + en vivo)
    openmct.telemetry.addProvider({
      supportsRequest: (o) => o.type === 'percy.telemetry',
      request: (o, { start, end }) => pedirHistorial(o.identifier.key, start, end),
      supportsSubscribe: (o) => o.type === 'percy.telemetry',
      subscribe: (o, callback) => escucharEnVivo(url, o.identifier.key, callback)
    });
  };
}
// Pieza 4: cada objeto lleva su ficha en domainObject.telemetry.values:
// [{ key: 'utc', format: 'utc', hints: { domain: 1 } },
//  { key: 'value', name: 'Velocidad', unit: 'm/s', hints: { range: 1 } }]
